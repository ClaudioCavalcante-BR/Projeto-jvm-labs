Origem dos dados

As instruções apresentadas são obtidas a partir dos arquivos .class compilados com Java 21 e inspecionados pela ferramenta javap. A API Java disponibiliza os opcodes, offsets e representações dos bytes para o navegador. A pilha de operandos e as variáveis locais são representadas por um interpretador didático implementado em JavaScript.

Nos experimentos de estruturas de decisão, a execução considera os desvios condicionais e incondicionais, respeitando os offsets das instruções JVM.

Nos experimentos de Race Condition, o Bytecode real é obtido da API. A interface demonstra didaticamente um incremento do contador compartilhado, sem reproduzir as 100.000 iterações de cada thread. A presença de synchronized é identificada pela flag ACC_SYNCHRONIZED do método.

No experimento de criação de objetos, a interface apresenta as instruções new, dup, ldc, bipush, invokespecial, astore, aload e invokevirtual. O laboratório demonstra como a JVM cria uma instância da classe Pessoa, executa seu construtor, armazena a referência em uma variável local e invoca o método apresentar(). A representação da pilha de operandos e das referências é didática, baseada no Bytecode real da aplicação.

No experimento 3.17.6, a API REST fornece o Bytecode real dos métodos executarThreadA() e executarThreadB(), compilados com Java 21. As instruções monitorenter e monitorexit demonstram a aquisição e a liberação dos monitores da JVM. O deadlock foi reproduzido em um processo Java separado e confirmado pelas ferramentas jcmd e jstack. A interface apresenta uma análise didática desse comportamento, sem executar um novo deadlock no servidor Spring Boot.
